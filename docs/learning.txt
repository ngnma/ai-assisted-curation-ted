0.1. src/build_vocab.py 
- Steps: 
    1. An LLM call to create a list of 20 broader concepts (roots of the hierarchy)
    2. An LLM call to assign each real tag from documents to each broader concept 
    3. Save tags+broader concepts into vocab/theasurus_draft.csv for human/AI review
- Learning: 
    1. Structured Output in LLM call using ollama.chat(format=schema) force LLM to answer in specific format.

0.2. src/review_vocab.py
- Steps:
    1. An LLM call to review each tag and its broader concept and check it among other broader concepts to find 
        whether current choice is best fit, otherwise suggest the better broader concept + reasoning
    2. Save all suggestions into vocab/theasurus_reviewed.csv for human review
- Learning
    1. Tool Call: write functions and pass them to LLM call so it can use as an available 
        tool ollama.chat(tools=[get_broader_concept, get_broader_concept_list])
        Then execute all tools which LLM request in response of that chat and provide results with a new message 
        which appends to the messages history so LLM have the history and the results and now can finish the first task.
    2. Tool Call: LLM knows which tool it should use based on name and """""" comments inside the functions (avalabile tools).
        So those comments should have a description of functionality and Args, outputs where aplicable.

0.3. Human Review 
- Steps:
    1. I review vocab/theasurus_reviewed.csv and apply changes based on my jusdgment and save the final version in vocab/theasurus.csv

0.4. export_skos.py
- Steps: 
    1. Convert vocab/theasurus.csv to vocab/ted_thesaurus.ttl
- Learning:
    1. SKOS: the standard format for thesauri. Four parts:
        skos:Concept: a term.
        skos:prefLabel: the term's name.
        skos:broader / skos:narrower: the parent and child links.
        skos:ConceptScheme: the thesaurus as a whole.

1.0. Unified Evaluation script for all methods -> evaluate.py
Steps:
    1. The main() function which runs when you run the code itself creates results/baseline_10_test.csv which has all metrics for 3 basic baseline models: most_frequent_tags, all_correct, random_tags. We will compare these numbers with all models.
    2. The evaluate() function is the core function we use for all models. It calculate F1@k, Precision@k, Recall@k and nDCG@k with bunch of other metrics for rare and near-miss tags.
    3. Metrics:
        Take one talk. Its correct (gold) tags are {education, children, teaching, science}, and the model’s top 5 are [education, technology, children, design, art]. Two of the five are correct.
        Precision@5 = correct in the top 5 ÷ 5 = 2/5 = 0.40. Of what I suggested, how much was right?
        Recall@5 = correct in the top 5 ÷ number of gold tags = 2/4 = 0.50. Of what I should have found, how much did I find?
        nDCG@5 = how good your list is compared with the best possible list, where correct answers count more the higher up they are.
            Each correct tag earns points depending on its position: position 1 earns 1.0, position 2 earns 0.63, position 3 earns 0.5, position 4 earns 0.43, and it keeps shrinking. That formula is 1 / log₂(position + 1).
            Model’s score: education at position 1 (1.0) + children at position 3 (0.5) = 1.5.
            Best possible score: all 4 gold tags in positions 1–4 = 1 + 0.63 + 0.5 + 0.43 = 2.56.
            nDCG = 1.5 / 2.56 = 0.59.
            “D” (discounted): lower positions are worth less.
            “n” (normalised): you divide by the perfect list, so the score is always between 0 and 1.
